# OpenLED

OpenLED is a compact arm-mounted addressable RGB LED board for OpenDrone builds.
It carries four WS2812B-V6 LEDs in one serial data chain and exposes 5 V, GND,
DIN and DOUT through solder pads. The board has no onboard controller,
regulator or logic-level translator.

## Architecture

OpenLED is a single 5 V LED chain.

LED data enters through J3 (DIN), passes through D1, D2, D3 and D4 in order,
and leaves through J6 (DOUT).

J1 and J2 provide the 5 V and GND input connections. J4 and J5 expose the same
5 V and GND rails at the opposite end of the board so another compatible load
or OpenLED board can be connected if required.

DOUT is regenerated by each WS2812B-V6 as the signal moves through the chain.
There is no onboard MCU, protocol converter or signal conditioning stage.

C1 and C2 provide bulk capacitance at opposite ends of the 5 V rail.

## Power

| Rail | Source | Distribution | Loads |
|---|---|---|---|
| 5 V | J1 | F.Cu 5 V plane | D1-D4, C1, C2, J4 |
| GND | J2 | B.Cu GND plane and local F.Cu GND zones | D1-D4, C1, C2, J5 |

The board expects an externally regulated 5 V supply.

Motor current must not pass through OpenLED.

## Connectors and I/O

All external connections are solder pads rather than fitted connectors.

| Connection | Ref | Function |
|---|---|---|
| 5 V input | J1 | 5 V supply input |
| GND input | J2 | Ground input |
| DIN | J3 | Addressable LED data input |
| 5 V output | J4 | 5 V pass-through |
| GND output | J5 | Ground pass-through |
| DOUT | J6 | Data output after D4 |

J1-J6 use the project-local `SolderPad_2.2x1.6mm` footprint and are excluded
from the BOM and position files.

## Layout rules

The PCB is 37 x 7 mm, 0.8 mm thick, two-layer FR4 with 35 um copper on both
outer layers and 1 mm board corner radii.

The four LEDs are placed on 7 mm centres.

The primary 5 V distribution is a global F.Cu copper zone. Ground is primarily
a global B.Cu plane, with local F.Cu GND zones at both ends of the board.

The three internal LED data links use repeated routing geometry and transition
between copper layers using vias.

The current board rules include:

| Constraint | Value |
|---|---:|
| General electrical clearance | 0.20 mm |
| Copper-to-board-edge clearance | 0.30 mm |
| Minimum hole-to-hole clearance | 0.50 mm |
| Default track width | 0.20 mm |
| POWER netclass track width | 0.50 mm |
| Standard via | 0.60 mm diameter / 0.30 mm drill |

The POWER netclass applies to `+5V` and `GND`.

Vias are tented on both sides.

Do not route motor current through this board.

Preserve short ground connections, continuous power copper and the existing
LED pitch unless a mechanical or electrical requirement justifies a change.

Mechanical fit on each intended OpenFrame size must be verified physically
before compatibility is considered final.

## Parts and datasheets

The root schematic is authoritative for the fitted components.

Parts already present in the shared OpenDrone catalogue should be reused from
`hardware/KiCad-Library/`.

Parts that are not yet present in the shared catalogue remain project-local
while OpenLED is in development.

The current WS2812B-V6 footprint and solder-pad footprint are stored in
`hardware/lib.pretty/`.

Orderable parts must retain exact `Manufacturer`, `MPN` and `LCSC` fields where
applicable.

Shared manufactured parts promoted at alpha or later must follow the OpenDrone
KiCad-Library datasheet and manifest requirements.

## Environment

Schematic check:

    kicad-cli sch erc hardware/OpenLED.kicad_sch

Board check, including schematic parity and refreshed zones:

    kicad-cli pcb drc --schematic-parity --refill-zones hardware/OpenLED.kicad_pcb

Netlist for scripted analysis:

    kicad-cli sch export netlist --format kicadsexpr -o /tmp/OpenLED.net hardware/OpenLED.kicad_sch

On Windows, `kicad-cli.exe` is installed with KiCad and may need to be called
using its full installation path if it is not in `PATH`.

Reusable OpenDrone scripts for renders, STEP export and release preparation are
external to this repository. Board-specific scripts, if any are added later,
belong in `hardware/tools/`.

## Rules

Identical in every OpenDrone board repo. Do not edit here; edit the template.

- **Never text-edit** `.kicad_sch`, `.kicad_pcb` or `.kicad_dru`. Use KiCad, or
  kicad-skip / the pcbnew API for scripted changes. `.kicad_pro` is JSON and may
  be edited directly for metadata.
- **Metadata yes, connections no.** An agent may write BOM and documentation
  fields (MPN, Manufacturer, LCSC, Cost, Datasheet, text variables). An agent
  may not change nets, wiring, routing, placement, footprint assignment, or any
  value that changes the circuit.
- **Close KiCad before any write to a KiCad file.** KiCad caches library tables
  at process start and overwrites files on save.
- **Reuse before you draw.** Check the `OpenDrone` library and its
  `PARTS-USED.md` first. If the part is there we have already sourced,
  footprinted and shipped it, and its symbol links to the exact committed
  datasheet: place it from `OpenDrone`. Draw a new part into `lib` only when
  the catalogue has nothing that fits, imported with
  `easyeda2kicad` from its LCSC number. Pulling a newer catalogue is a
  deliberate, reviewed commit: `git submodule update --remote
  hardware/KiCad-Library`, then DRC.
- **One person holds a board layout at a time.** KiCad files do not merge. Say
  on Discord that you are taking it. See [CONTRIBUTING.md](CONTRIBUTING.md).
- **Run ERC and DRC before every pull request.** Existing approved findings
  may remain; a new type or increased count must be reviewed before merge.
  Commands are in Environment above.
